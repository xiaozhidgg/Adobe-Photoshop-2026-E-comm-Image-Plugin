## 0. 结论（TL;DR）

| 档 | 目标 | 可行性 | 卡点 |
|---|---|---|---|
| **A 摆正**（旋转 ± 微梯形） | 把"拍歪了"的产品转正（水平/垂直线对齐画布） | **高** | 主体主轴角度检测（我们自己算） |
| **B 透视拉平**（梯形→矩形） | 把"斜上方 / 斜侧拍"拉成正视 | **中** | **4 个角点从哪来**（不是变换本身） |

**能做的是"摆正"和"拉平"，做不到的是"换视角"。**

## 1. 非目标（明确排除）

- 单图「侧面 → 正面」「俯视 → 正视」重投影：PS 没有可信的单图视角重投影接口；生成式补全属于重新生成，不算矫正，且会改动产品外观（电商场景不可接受）。
- 全自动无交互的 B 档：只有在"产品近似矩形"时算法猜角点才靠谱；异形（瓶身）无解。

## 5. 风险与安全设计

1. **最大风险是误判**：产品本来就斜放（斜靠的瓶子、45° 摆拍）→ 强行摆正会毁图。
   - 策略：θ < 3° 且四边拟合好 → 只做微调；θ > 15° 或拟合残差大 → **跳过并在面板写明原因**。
   - 面板默认关；日志写清"做了什么 / 为什么跳过"。
2. **可选步骤失败不得掐死整条流程**（§17 教训）：失败只 `log("warn", ...)` 并继续。
3. **幂等**：变换后写"已摆正"标记，禁止重复变换（每次像素变换都会重采样一次）。
4. **不进关键链路**：不要为了摆正引入周期性 `executeAsModal`（会闪文档 / 阻塞用户，见 `docs/RESEARCH-plugins.md` §3⑦）。
5. 回退：沿用现有快照机制（一键撤销到本步骤前）。

## 8. 多物体（两个及以上产品）

**关键不是"检测几个物体"，而是先分清它们是不是同一个平面** —— 单应变换本质是"一个平面 → 一个平面"，一张变换救不了两个朝向不同的物体。

| 情况 | 例子 | 做法 |
|---|---|---|
| 同一平面、同一朝向 | 两个盒子并排放在同一张桌上、同一张照片 | **一个变换即可**：当一组，用并集算 4 角 |
| 不同平面 / 不同朝向 | 一正一斜靠、一前一后 | 一个矩阵救不了 → **逐物体变换**（各自 4 角、以各自 bbox 中心为基准） |

### 8.1 怎么知道有几个物体

1. 主体 alpha（`ps.getSubjectPixels({ applyAlpha:false, maxDim:1024 })`）→ 阈值 128 → 二值；
2. **闭运算**（3×3 膨胀 2 轮 → 腐蚀 2 轮）—— 防"瓶身+瓶盖"这类细长连接被切断；
3. 连通域标记（两遍扫描 / 并查集，约 40 行）；
4. **面积过滤**：< 画布 1% 当噪点丢弃；保留 2–5 个；
5. **合并规则**：两分量 bbox 间距 < `min(两者宽度)/4` → 判为**同一物体**（避免误拆）
   —— ★ **实现时有意偏离**：这条会在「两个商品挨得近」时把不同物体合成一个、把并集倾斜错误原样复现（真机那张间距 52px < 65px）。
   最终只并**间距 ≤ 3px 的细缝**（抗锯齿/白描边），见 §10.9。；
6. 每个分量各算：面积 / bbox / 主轴 θ / 最小外接四边形 + 四边拟合残差。
   分组判据：θ 差 < 3° 且各自残差都小 → **同平面组**（一次变换）；否则各自一组。

### 8.2 粘连 / 遮挡：无解，交回人

两个物体互相贴住时单靠 alpha 分不开（PS 的 `removeBackground` 也是整体处理）。面板只能写「检测到多个物体且粘连，请手动分层，或只处理主物体」——不要硬猜。

### 8.3 PS 侧要多一个"分物体"环节

1. 从每个分量生成选区（写法：`to: { _ref:"channel", _enum:"channel", _value:"transparencyEnum" }`，或用分量多边形设选区）；
2. **通过拷贝的图层**（layer via copy）→ 一物一层；
3. 逐层各自取 4 角 → 以**各自 bbox 中心**为基准变换；
4. 最后才谈排布。

⚠️ **顺序硬约束**：分层必须在「应用蒙版（烘焙进像素）」**之前**做（烘焙后像素固定、分层不可逆），流程因此变成
`抠图 → 分物体（新）→ 逐物体摆正（新）→ 背景 → 接地投影 → 调色 → 尺寸构图 → 导出`

### 8.4 摆正之后怎么摆 —— 产品决策，必须由用户选

| 意图 | 效果 | 场景 |
|---|---|---|
| 保持原相对位置（默认） | 只各自旋转，不重排 | 最保守，不改变原构图意图 |
| 对齐 | 同一水平中线 / 同一底线 | 两件套、主副图 |
| 等距排列 | 水平居中 + 等间距 + 等宽 | 目录图、对比图 |

另外：投影是**各自一份**（前后不同高度）还是**共用一份**（同平面）也要定；背景仍只有一层。建议面板给一个下拉，默认「保持原相对位置」。

### 8.5 对现有流程的影响

- 居中 / 缩放：现在用 union bbox → 多物体天然正确（居中整组），**不用改**；
- 接地投影：同平面一份即可；不同高度才需各自一份（按各自底边算 `localLightingAngle`）；
- 导出多尺寸：画布级，不受影响。

### 8.6 分档与边界

- 归为 **D 档**，排在单物体 A/B 档**之后**：先做单物体只读探针（§9），再谈多物体。
- D 档新增：连通域 + 合并规则 + 分层 + 排布选项 + 逐层变换 + 各自投影；**2–3 轮**，且需真机验证"分层不破坏蒙版烘焙结果"。
- 诚实边界：粘连 / 遮挡无解；异形瓶不会被自动摆正（残差大 → 跳过）；两物体朝向差异过大时"各自摆正"可能让画面变怪 → 默认只给"保持相对位置"，任何重排都要用户显式选。

### 10.2 安全设计（逐条对应 §5）

- 只在 `verdict==="micro"` 且 |tilt| ≥ 0.2° 时才旋转；confirm（5°~15°）与 skip（>15° / 残差大 / 异形）一律零改动，只写日志。
- 幂等：|θ| < 0.2° 直接返回 `already-level`（不重复重采样）。
- **方向不靠猜**：转完重读像素再分析，|θ| 变小才算成功；只有「确实转向另一侧」才反向补一次（净效果＝另一个方向）并建议改 `PS_ANGLE_SIGN`；θ 基本没变 ⇒ 判 `no-effect` 立即停止，绝不盲转。
- **回读基准与首测一致**（`detect(..., first.maskMode)`）：否则旋转后图层四角变透明，掩膜会从「主体」跳到「整张画布」，量到的 θ 恰是画布被转过去的角度（真机事故：`θ 2.04° → −2.04°` 就是这个假信号）。
- 失败只告警不中断：`reason ∈ not-micro / already-level / layer-locked / transform-rejected / no-effect / readback-failed / wrong-direction / failed`，`stepStraighten` 把 `ok:false` 转成 `ok:true` + `reason:"failed"`（§5「可选步骤失败不得掐死流程」）。
- 不裁剪、不缩放、不 flatten；只在真正旋转时进 modal（不进关键链路、不做周期性 `executeAsModal`）。

### 10.4 A 档期间挖出的三条 PS 硬事实（已写进 `docs/INTERFACE.md` §12.2）

1. **背景层转普通层会换 id**（真机 1 → 2，名字变「图层 0」），而且 PS **同时会回一个错误项**；「旧 id 读不到」不等于"还锁着" ⇒ 必须以状态为准并改用新 id，否则后续命令全打在一个不存在的图层上、被「命令…当前不可用」挡下，表现为"第一次点击永远失败、第二次点击才成功"。
2. **改掉名字才算转换**：`set` 传回原名「背景」不会转换；转换名用「图层 0」。
3. **`transform` 只作用于当前激活图层** ⇒ 必须 `select` 再 `transform`；`set` / `select` / `rasterizeLayer` 在刚打开的文档上被拒「当前不可用」时，真因往往是旧 id 已失效，而不是"宿主忙"。

### 10.5 剩余项

- B 档：`lensCorrection` / `adaptiveWideAngle` / Camera Raw Upright 在均**不可调用**，`distort` ＝ "分布"（Distribute），`transform` 只证成 `Angl`，`quad` 四角形态既不能证明也不能证伪 ⇒ 详见 `docs/PROBE-straighten.md` §6/§7。
- D 档（多物体）与 §8.4 的摆位策略（保持原相对位置 / 居中 / 贴边）仍是**产品决策**，未定。

### 10.6 成组复测挖出的缺陷：竖版主体被误判成「斜放」（已修）

- 做法与理由：
  - 用**矩形选区**限定旋转范围（有选区时 PS 只变换选区内内容、旋转中心＝选区中心）。宿主没有 putPixels/载入选区的

    `ceil(0.5*sqrt(bw²+bh²)*tan|tilt|) + 2`（容纳旋转后伸出的角）。
  - ★ **旋转前先烘焙图层蒙版**（`ps.applyUserMask`）：选区内的 transform 不会带着蒙版一起转，不烘焙则转出去的
    边角被旧轮廓裁掉（物体顶端仍是水平切口）。烘焙失败 ⇒ 零变换（宁可不动）。烘焙后回读只能走像素基准。
  - ★ **邻居保护**：物体外扩后的选区若罩住另一个物体的包围盒，则该物体跳过（宁可不转，也不能把旁边的好物体转歪）。

    中心，把物体整体挪走（这种「转正了但跑位了」必须判失败）。
